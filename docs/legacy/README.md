# docs/legacy — the original game as a reference table

The original game's values were extracted **once** from `.legacy/deobfuscated/` so nobody has
to re-read or re-parse the ActionScript to find a number.

| File | What it is |
|---|---|
| `legacy_values.json` | Machine-readable reference: runtime turret defaults (class constructors), GameManager/AttackerManager tables, combo data and recipe structure, maps, challenge presets and pickers, tutorial pages, engine constants, sound/art mappings, the original mod-editor defaults and descriptors, and every place the runtime defaults differ from the mod editor. Generated by `tool/legacy_extract.dart`. |
| `LEGACY_VALUES.md` | The same values as readable tables. Generated; do not edit. |
| `ENGINE_NOTES.md` | Narrative: formulas, timings, quirks and open questions, with citations. |

How it is used:

- `tool/gen_data_from_legacy.dart` turns `legacy_values.json` into `assets/data/*.json` (the
  game's schema). The data snapshot test (`packages/onslaught_core/test/data/snapshot_test.dart`)
  fails if `assets/data` drifts from what the table generates, so a value can only change by
  changing the table (with a citation) or by a documented deviation.
- `.legacy/` is gitignored: it stays on developer machines for re-extraction and asset export
  only.
- `tool/legacy_extract.dart` and `tool/legacy_extract/` hold the AS2 literal reader. The full
  extraction needs `.legacy/` and is kept to audit or extend the table, not run by the build or
  tests. The table has two kinds of section:
  - **Parsed** from `.legacy/` (turrets, GameManager/AttackerManager, combo `data`, maps,
    challenges, tutorial, mod editor, discrepancies). A wrong value here is fixed in the
    reader or, if the source really says it, recorded as a deviation; re-run the full
    extraction.
  - **Transcribed** by hand in `tool/legacy_extract/engine_constants.dart` (`engine`, the combo
    recipe structure `combos.recipes`/`unreachable`/`combonly`, `gameManager.modeRacks`; listed
    in `tool/legacy_extract/transcribed_sections.dart`). Edit only `engine_constants.dart`, then
    run `fvm dart run tool/legacy_extract.dart --transcribed`, which rewrites just those
    sections of the table (and `LEGACY_VALUES.md`) without `.legacy/`.
    `test/tool/legacy_transcription_test.dart` fails in CI while the two disagree.

  Then regenerate the data (`fvm dart run tool/gen_data_from_legacy.dart`) and note the change,
  with its citation, in the commit.

Important finding recorded here: the original **runs on the class constructors**, not on
`mods/ModDefaults.as`. The mod editor's defaults differ in a few places (e.g. Blue damage step
8 is 18 400 in play, 19 400 in the editor); the table lists them under `discrepancies`.
